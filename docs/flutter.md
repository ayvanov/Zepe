# План миграции Zepe в Flutter

## Цель

Перенести текущее приложение Zepe (Deno + Hono + SSR HTML + PWA) в Flutter-приложение с сохранением текущей бизнес-логики расчётов зарплаты и улучшением архитектуры, UX и поддержки платформ.

---

## Этап 0. Зафиксировать текущее поведение (baseline)

1. Сформировать список текущих функций:
   - ввод/сохранение зарплаты;
   - расчёт выплат по месяцам и датам;
   - отображение списка месяцев с суммами и датами;
   - API-запросы к `isdayoff.ru`;
   - офлайн-кэш и PWA-поведение.
2. Зафиксировать входные/выходные данные:
   - параметры расчёта (`salaryMultiplier`, `advanceDays`, `advancePayDay`, `restPayDay`);
   - формат API и month-slices.
3. Сделать эталонные сценарии проверки:
   - 3–5 наборов зарплата/год и ожидаемый результат по нескольким месяцам.
4. Зафиксировать текущие UX-решения:
   - экран настроек;
   - поведение роутинга;
   - формат валюты/локали (`ru-RU`).

**Результат:** документ с функциональными и вычислительными эталонами для проверки Flutter-версии.

---

## Этап 1. Спроектировать целевую архитектуру Flutter

1. Выбрать слои:
   - `presentation` (экраны/виджеты);
   - `domain` (модели, use-cases, правила расчёта);
   - `data` (API, кэш, локальное хранилище).
2. Разложить текущие сущности:
   - `MonthMeta` → `domain/models/month_meta.dart`;
   - форматирование денег/дат → `core/formatters`.
3. Спроектировать сервисы:
   - `IsDayOffApiClient`;
   - `YearSlicesRepository` (network + cache);
   - `SalarySettingsRepository`.
4. Выбрать state management:
   - рекомендовано `Riverpod` или `Bloc` (фиксировать в ADR).
5. Определить маршруты:
   - `HomeScreen`;
   - `SettingsScreen`;
   - (опционально) `YearSummaryScreen`.

**Результат:** архитектурная схема + структура директорий + техническое решение по стейт-менеджменту.

---

## Этап 2. Создать Flutter-проект и базовый каркас

1. Инициализировать новый Flutter-проект.
2. Настроить локализацию (`intl`, `ru` по умолчанию).
3. Подключить зависимости:
   - HTTP-клиент (`dio`/`http`);
   - state management (`riverpod`/`bloc`);
   - локальное хранилище (`shared_preferences`/`hive`);
   - кэш (`hive`/`sqflite`), при необходимости.
4. Настроить темы:
   - светлая + тёмная;
   - типографика и базовые цвета.
5. Добавить линтеры и форматирование:
   - `flutter_lints`, `analysis_options.yaml`.

**Результат:** запускаемый каркас приложения с пустыми экранами и навигацией.

---

## Этап 3. Перенести бизнес-логику расчётов 1:1

1. Переписать алгоритм `MonthMeta` на Dart без изменения формул.
2. Реализовать:
   - расчёт рабочих/выходных дней по slice;
   - расчёт аванса/остатка;
   - вычисление дат выплат.
3. Вынести константы в конфиг/настройки.
4. Покрыть юнит-тестами:
   - совпадение с baseline-результатами;
   - граничные случаи (нулевая зарплата, отсутствующие данные следующего месяца).

**Результат:** модуль расчётов в Flutter даёт идентичные результаты текущему приложению.

---

## Этап 4. Реализовать data-слой (API + кэш)

1. Реализовать клиент к `https://isdayoff.ru/api/getdata`.
2. Перенести логику `fetchYearSlices(year)`:
   - загрузка целого года;
   - префетч января следующего года.
3. Добавить обработку ошибок:
   - таймауты;
   - ретраи;
   - fallback на кэш.
4. Реализовать кэш с TTL:
   - ключи: `year`, `nextYearJanuary`;
   - стратегия invalidation.
5. Добавить офлайн-режим:
   - если сеть недоступна, отдавать последнее валидное значение.

**Результат:** стабильный data-слой с предсказуемым поведением при сбоях сети.

---

## Этап 5. Собрать UI, эквивалентный текущему

1. `HomeScreen`:
   - заголовок с текущим годом;
   - список месяцев;
   - блоки выплат (сумма + дата);
   - состояние прошедших выплат (аналог `past`).
2. `SettingsScreen`:
   - поле зарплаты;
   - валидация;
   - сохранение в локальное хранилище;
   - мгновенное обновление расчётов.
3. Форматирование:
   - валюта RUB;
   - русские названия месяцев/дней.
4. Состояния UI:
   - loading;
   - empty;
   - error с кнопкой retry.

**Результат:** пользователь получает тот же функционал, но в нативном Flutter-интерфейсе.

---

## Этап 6. Платформенные задачи и выпуск

1. Иконки/сплэш:
   - перенести ассеты и сгенерировать platform-specific ресурсы.
2. Flutter Web:
   - если нужен PWA-режим, настроить service worker Flutter Web.
3. Android/iOS:
   - проверить permissions и min SDK;
   - подготовить release-конфиги.
4. CI/CD:
   - `flutter analyze`;
   - `flutter test`;
   - сборки для целевых платформ.

**Результат:** готовые сборки для web/mobile с единым кодом.

---

## Этап 7. Качество, наблюдаемость, миграция пользователей

1. Тесты:
   - unit для расчётов;
   - widget tests для ключевых экранов;
   - integration tests критических сценариев.
2. Логирование/ошибки:
   - централизованный обработчик ошибок;
   - (опционально) Crashlytics/Sentry.
3. План миграции данных:
   - перенос сохранённой зарплаты из веб-версии (если актуально для Flutter Web);
   - поведение при первом запуске.
4. Пошаговый rollout:
   - beta-канал;
   - сравнение результатов со старой версией;
   - финальный switch.

**Результат:** безопасный переход без регрессий и с контролируемым релизом.

---

## Рекомендуемый порядок выполнения (коротко)

1. Baseline и тест-кейсы.  
2. Архитектура + каркас Flutter.  
3. Перенос расчётов + unit-тесты.  
4. API/кэш/офлайн.  
5. UI + настройки.  
6. Платформенные доработки и релиз.  
7. Наблюдаемость и rollout.

---

## Критерии готовности (Definition of Done)

- Расчёты Flutter совпадают со старой версией на эталонных сценариях.
- Настройки зарплаты и год работают стабильно.
- Ошибки сети обрабатываются, офлайн-кэш работает.
- Приложение проходит линтеры и тесты.
- Есть релизные сборки для целевых платформ.
- Документация по архитектуре и запуску обновлена.
