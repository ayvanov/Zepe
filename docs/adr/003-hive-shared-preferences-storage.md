# ADR 003: Выбор Hive и SharedPreferences для локального хранения

**Дата:** 2025-02-28  
**Статус:** Принято

## Контекст

Приложению требуется локальное хранение для:
1. **Кэш year-slices** — данные о рабочих днях на год (TTL 24 часа)
2. **Настройки пользователя** — оклад, коэффициенты, дни выплат

Требования:
- Быстрое чтение/запись
- Поддержка TTL для кэша
- Минимальный размер хранилища
- Простота использования

## Решение

Использовать **два хранилища**:

### 1. Hive для кэша year-slices
**Причины:**
- Быстрое NoSQL хранилище
- Поддержка сложных структур данных
- Ручное управление TTL через метаданные
- Асинхронный API
- Минимальный оверхед

**Структура данных:**
```dart
{
  'year': 2025,
  'yearDataRaw': '1,2,3,...',
  'nextJanuaryRaw': '1,2,3,...',
  'updatedAt': '2025-02-28T10:00:00Z'
}
```

### 2. SharedPreferences для настроек
**Причины:**
- Простые key-value пары
- Встроенная поддержка примитивных типов
- Синхронный API для чтения
- Идеально для пользовательских предпочтений

**Ключи:**
- `settings_salary` (double)
- `settings_multiplier` (double)
- `settings_advance_days` (int)
- `settings_advance_payday` (int)
- `settings_rest_payday` (int)

## Альтернативы

### Room (через drift)
- **Плюсы:** SQL, миграции, строгая схема
- **Минусы:** Избыточен для простого кэша, сложнее настройка

### Isar
- **Плюсы:** Быстрый, schema-less
- **Минусы:** Меньше сообщество, менее зрелый

### Firebase Firestore
- **Плюсы:** Синхронизация между устройствами
- **Минусы:** Требует интернет, избыточен для локальных данных

### SQLite (sqflite)
- **Плюсы:** Надёжный, знакомый SQL
- **Минусы:** Медленнее Hive для простых операций

## Последствия

### Положительные
- Оптимальная производительность
- Разделение ответственности (кэш vs настройки)
- Простая реализация

### Отрицательные
- Две зависимости вместо одной
- Ручное управление TTL
- Нет автоматической миграции схемы Hive
